## AppSetting — 應用設定

- **功能：**
    - 資料管理：帳戶與類別的 CRUD、CSV 資料匯入與匯出、清除所有資料。
    - 偏好設定：外觀主題、貨幣與財務設定、語言與時區、分析同意。
    - 方案：付費升級入口，免費版限定顯示。
- **目的：**
    - 提供使用者統一的設定入口。
- **做法：**
    - 應用設定頁面作為模組根頁面，以 Section 分組呈現三大功能區塊；各子頁面以 Stack 導航進入。
- **排除：**
    - 作業系統層級的權限授予，例如通知、相機、定位，由 iOS/Android 系統設定管理。app 內的分析同意開關屬偏好設定。

### DataManagement — 資料管理

- **功能：**
    - 帳戶與類別的進入點，導向各自的 CRUD 頁面。
    - 資料匯入匯出 CSV 格式。
    - 清除所有資料。
- **目的：**
    - 讓使用者集中管理記帳的基本資料結構，以及進行資料備份與還原。
- **做法：**
    - 資料管理頁面提供三個入口：類別管理、帳戶管理、資料操作；資料操作頁面再拆分為匯入、匯出、清除所有資料三個子區域。
- **排除：**
    - 帳戶餘額自動從銀行拉取；AI 自動分類建議。

#### CategoryCRUD — 類別管理

- **功能：**
    - 建立、編輯、停用類別。
    - 首次啟動建立預設類別。
- **目的：**
    - 讓使用者依個人消費習慣組織財務分類，支撐報表統計準確度。
- **做法：**
    - 預設類別含三個支出概念。
    - 預設類別含兩個收入概念。
    - 預設名稱依首次啟動語系建立。
    - 預設類別可編輯、停用與刪除。
    - 預設類別計入免費數量上限。
    - LEVEL_1 可無限新增類別。
    - 停用不刪除，歷史交易保留關聯。
- **排除：**
    - AI 自動分類建議，屬 Cloud Service / AIAdvisor / Backend 負責範疇。

#### AccountCRUD — 帳戶管理

- **功能：**
    - 建立、編輯、停用帳戶。
    - 設定帳戶幣別。
    - 首次啟動建立現金與信用卡帳戶。
- **目的：**
    - 讓使用者將資產對應到真實的銀行帳戶、現金或投資帳戶。
- **做法：**
    - 預設帳戶採裝置預設幣別。
    - 預設名稱依首次啟動語系建立。
    - 預設帳戶可編輯、停用與刪除。
    - 本地資料庫儲存。
    - 停用不刪除，歷史交易保留關聯。
- **排除：**
    - 帳戶餘額自動從銀行拉取。

#### DataOperations — 資料操作

- **功能：**
    - CSV 匯入：交易、轉帳。
    - CSV 匯出：交易、轉帳。
- **目的：**
    - 讓使用者可以透過 CSV 進行資料備份、還原或從其他工具遷移資料。
- **做法：**
    - 匯入採四步驟 Wizard: 選擇檔案 → 欄位對應 → 內容比對 → 預覽確認
    - 匯入把關採欄位守門，必填欄位須整欄格式合格才可對應
    - 必填欄位含空值或非法格式的檔案，擋於欄位對應步，修正後重新匯入
    - 空值與格式壞值不做逐列略過，可選欄位容許空值
    - 超出儲存範圍的金額於匯入執行時逐列略過並計入略過數
    - 匯出生成 CSV 並呼叫系統分享介面
- **排除：**
    - 雲端自動備份由 CloudSync 負責
    - 匯入格式目前僅支援 CSV，不支援 OFX、QIF 等格式。

#### DataErase — 清除所有資料

- **功能：**
    - 清除所有資料：app 內一次抹除雲端資料、本機資料與內部身分。
- **目的：**
    - 保障資料自主權，提供完整的資料退出路徑。
- **做法：**
    - 入口住資料管理頁，與匯入匯出同居。
    - 清除採兩段確認：說明段明示雲端、本機、身分全滅且不可復原；最終段以破壞性樣式按鈕確認。
    - 有效訂閱者於說明段註明訂閱跟隨 Apple ID、不受清除影響，並提供直達訂閱管理頁的按鈕。
    - 清除由 CloudFunctions 以伺服器權限執行：清除該身分的雲端資料、刪除授權紀錄與交易歸戶索引、刪除 Auth 身分。
    - 本機硬刪該身分的資料列。
    - 完成後自動重生新匿名身分，使用者直接續用。
    - legacy Sign in with Apple 身分由伺服器判定並撤銷授權；撤銷未完成不擋清除，完成後引導於系統設定手動撤銷。
- **排除：**
    - 清除前資料打包下載，備份由資料管理的 CSV 匯出承擔。
    - 延遲清除與反悔期，確認即清、不設等待窗口。
    - 訂閱代退與代取消，App Store 訂閱僅能由使用者在 Apple 端管理。
- **利弊：**
    - app 內即點即清承載資料自主權，但誤觸不可復原，僅靠兩段確認防呆。
    - 訂閱真相在 StoreKit 跟 Apple ID 走，清除後付費照樣有效。

### Preference — 偏好設定

- **功能：**
    - 外觀：配色主題、啟動模式。
    - 貨幣與財務：基礎貨幣、幣別顯示格式、匯率管理。
    - 語言與時區：語言切換、時區設定、週起始日。
    - 使用分析同意由 `usageAnalyticsConsent` 控制。
- **目的：**
    - 管理所有影響全 App 呈現與行為的個人化偏好設定。
- **做法：**
    - 偏好狀態集中管理，持久化於本地資料庫；本地設定即唯一真相，永不從雲端下載套用。
    - 設定變更即時反映，並由 PreferenceUpload 單向上傳 Firestore，供未來分析使用。
    - 上傳為欄位級覆寫，無 Last-Write-Wins、無衝突解決、不設 device 欄位；接受 Firestore 與各裝置欄位級不一致。
    - 跨裝置一致由使用者主動匯出匯入銜接，無雲端即時同步。
    - `analyticsConsent` 保留相容欄位。
    - 財務分析同意預設關閉。
    - 偏好設定不顯示財務分析開關。
    - 財務分析管線上線前另行詢問。
    - `usageAnalyticsConsent` 預設關閉。
    - 首次啟動顯示一次同意詢問。
    - 同意後才啟用事件蒐集。
    - 拒絕後維持停用。
    - 選擇結果記錄於本機。
    - 偏好設定顯示使用分析開關。
    - 開關不顯示說明文字。
    - 同意狀態只存本機。
    - 使用行為不含記帳內容。
    - 使用行為不設定 user id。
- **上游對應：**
    - analyticsConsent 對應財務內容分析退出機制。
    - `usageAnalyticsConsent` 對應使用行為分析。
    - 兩者對應 AnalyticsPipeline。
- **排除：**
    - 使用者自訂調色盤
    - 自動依裝置地區選擇時區

#### Appearance — 外觀設定

- **功能：**
    - ThemeSystem：主題切換介面。
    - LaunchModeSetting：設定 App 啟動後預設導航目標
      - 首頁
      - 支出
      - 收入
      - 轉帳
- **目的：**
    - 透過視覺設計降低記帳焦慮，增加日常使用黏著度
    - 讓高頻記帳的使用者省去每次點擊的步驟
- **做法：**
    - 主題設計以全域 Token 管理
    - 確保跨頁面顏色、字體、間距一致，禁止寫死
    - 啟動模式偏好設定即本地真相，App 啟動直接讀本地、依設定決定初始導航；變更後同走 PreferenceUpload 單向上傳
- **排除：**
    - 使用者自訂調色盤
    - 依時間或情境自動切換啟動模式

#### CurrencyAndFinance — 貨幣與財務設定

- **功能：**
    - 基礎貨幣設定：設定報表計算使用的基礎貨幣。
    - 幣別顯示格式設定：設定各幣別的小數位數與千位單位顯示，逐幣別配置；點入單一幣別可細部編輯。
    - 匯率管理：手動輸入並儲存外幣對基礎貨幣的匯率，可新增或編輯單筆匯率記錄。
- **目的：**
    - 讓多幣別帳戶的報表可以統一換算為使用者熟悉的貨幣呈現
    - 確保各幣別依慣例正確呈現金額格式
    - 維持完整離線匯率管理能力
- **做法：**
    - 基礎貨幣偏好持久化於本地設定
    - 各幣別顯示格式逐幣別獨立配置，全 App 統一取用
    - 匯率採 Strict Direct Rate——僅使用外幣對基礎貨幣的直接匯率計算報表，不支援中間跳轉
    - 匯率採追加記錄策略，可透過新增記錄修正歷史
- **排除：**
    - 外部即時匯率 API
    - 同時支援多種基礎貨幣檢視
    - 自動依 ISO 4217 標準套用格式
- **利弊：**
    - 完全離線可用，且匯率可反映使用者實際換匯成本，但使用者需自行維護，若疏於更新則報表數字失真。
    - Strict Direct Rate 不支援跳轉，若無外幣到基礎貨幣的直接匯率，該筆資產在報表中無法計算。
    - 單一基礎貨幣使報表計算邏輯簡單，但使用者若同時操作多種主要貨幣，只能選擇其中一種作為基準。

#### RegionAndLanguage — 語言與時區設定

- **功能：**
    - LanguageSetting：應用程式語言切換，支援 20 個語系——英文、繁體中文、簡體中文、日文、韓文、德文、西班牙文、法文、葡萄牙文巴西版、義大利文、荷蘭文、瑞典文、丹麥文、挪威文、芬蘭文、波蘭文、印尼文、越南文、泰文、印地文。
    - TimeZoneSetting：時區設定，影響日期邊界計算。
    - WeekStartSetting：週起始日設定，影響週粒度期間的分組邊界與週報表呈現。
- **目的：**
    - 確保報表日期邊界與使用者所在地區一致，並以母語呈現介面。
    - 觸及非英語系全球市場，降低使用摩擦。
- **做法：**
    - 語言切換透過本地化框架管理
    - 首次啟動讀取裝置語系，與 20 個支援清單比對；匹配則自動套用
    - 比對未匹配時 fallback 統一回英文，不做語族內 fallback，避免繁簡混雜或非預期語系出現
    - 設定頁提供搜尋介面，依語系代碼或原生名稱即時篩選，方便使用者於眾多語系中快速定位
    - 語系項目以原生名稱呈現，例如 English、日本語、한국어、Español，不另附中文譯名
    - 時區以標準時區識別碼 IANA 格式儲存，日期邊界計算依照該設定執行。
    - 週起始日三值——auto 依語系慣例推導、週日、週一；明確值覆蓋語系慣例，與其他偏好同走本地真相與單向上傳。
- **排除：**
    - 自動依裝置地區即時更新語言或時區，避免跨國旅行時介面頻繁切換
    - 在語系項目顯示國家國旗，避免在多國共用語系時牽涉政治敏感
    - 阿拉伯文、希伯來文等 RTL 從右到左排列語系，避免 layout 鏡像翻轉的工程成本
    - 俄文，避免 Apple Pay 與 Google Pay 在當地受限導致無法收費
- **利弊：**
    - 明確時區設定避免跨時區記帳時日期錯誤，但使用者需主動設定，預設值可能不符當前所在地。
    - 20 個語系覆蓋全球 App 消費市場主要區域，但翻譯品質依賴 LLM 機翻初稿，部分專有名詞可能詞不達意。
    - 每加一個語系，未來新功能都要同步加 i18n key，維護成本線性疊加。

### Plan — 方案升級入口

- **功能：**
    - 免費版用戶限定顯示的付費升級入口，導向付費牆頁面。
    - 付費後此 Section 自動隱藏。
- **目的：**
    - 在設定頁提供低門檻的升級入口，讓免費用戶在操作設定時也能觸及升級路徑。
