# R00 靜態驗證

- **涵蓋測項:** 一百零二個單元測試層檢查點，跨測項不分場
- **前置場次:** 無
- **起點狀態:** 不依賴任何 app 資料狀態
- **終點狀態:** 不改變任何 app 資料狀態
- **前置環境:**
    - app impl 主 checkout node_modules 完整
    - functions 內 node_modules 裝妥
    - 不需裝置、不需 Metro、不需連網憑證
- **fixture 引用:** 大型歷史資料組
- **預估時長:** 15 分鐘
- **步驟表:** `no2_r00_static_verification.csv`

排最前的理由。單元測試與 app 執行狀態零相依，跑一次即收下全部單元測試層檢查點。原設計十二場各跑一次全套、等於同一批測試跑十二遍。先跑本場可快速失敗，測試已紅時不必先耗掉整輪手動場次。

序 1 為版本綁定檢查。跑測試前先確認主 checkout 停在待驗版本，不符即停。否則整場綠燈驗的是別的 commit、且不會有任何訊號提示。

本場只執行兩次測試，序 2 一次 app、序 3 一次後端。其餘各列自該兩次結果核對對應測試檔、不重跑。說明欄標的手動場次僅供追溯，不代表執行順序相依。

核對列的動作欄直接寫測試檔路徑，取自 `npx jest --listTests`。寫散文群名會在測試檔改名時靜默失配，路徑則 grep 得出來。大型歷史案例只使用固定生成資料。Native adapter 另以專屬測試鎖定 SQL 契約。兩者都不引用個人匯入資料。

執行指引三句。照步驟表列序走、一列一步。已驗欄是該步收下的檢查點、多條以全形分號分隔。類型為 Claude節點 的列停下等 Claude 或依說明貼回輸出。
