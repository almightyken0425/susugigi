# 本次測試的執行分工

測項定義操作與必要證據。本文件安排這次由誰完成工作。
分工由 `test-run` 協調，只留目前 session，不回寫成產品能力限制。
`test-ios` 繼續持有 Simulator 環境、觀測與清理生命週期。

## 沿用偏好，核對能力

先沿用使用者已表達的選擇。沒有指定時，AI 承接已授權且能完成的工作。
使用者可以選擇整場或部分步驟自己操作，也可以只觀看指定結果。
這些選擇在本輪持續有效，不逐步重問。

能力按目前平台、裝置與工具確認。先檢查方法所需環境，再確認操作者能取得必要觀察及完成操作。

| 操作需求 | 當次要核對的能力 |
| --- | --- |
| `ui` | 能定位目標 App、讀取目前畫面並使用所需手勢。AI 需要可用的 UI 工具，使用者操作時要有可操作的目標畫面。 |
| `device-ui` | 除 UI 能力外，核對已鎖定的實體裝置與要求的證據通道。Simulator 能力不能代替實機能力。 |
| `tool` | 所需命令、探針或工具入口可用。操作者能在既有授權與隔離條件內使用，並取得指定證據。 |
| `unavailable` | 尚無操作路徑，依既有能力阻斷規則處理。換人不解除阻斷。 |

模型更新、工具安裝或過去成功不能單獨證明本次就緒。
先用零副作用方式檢查工具與畫面。只能透過實際操作確認的能力，在已授權測項中取得證據，不另造有副作用的探測。
缺少 AI 操作能力時，可以把受影響步驟交給願意操作的使用者。必要證據或環境缺少時仍按原規則阻斷。

## 安排本輪工作

使用[範本中的本次安排表](test_step_template.md)，或直接沿用目前 session 的執行記錄。
簡短測試不必新增檔案。至少能看出以下分配。

- 準備與清理的負責者，以及各自完成條件。
- UI 操作者。需要分段時引用場次、步驟或檢查點。
- 證據取得者、來源及取證時點。
- 使用者要觀看的結果、畫面停點及續做方式。

客觀判定仍由 `test-run` 對照預期與證據完成。使用者想親自看畫面，不代表必須親自操作。
AI 能操作，也不代表可以跳過使用者已指定的觀看或操作安排。

| 本次偏好 | 工作安排 |
| --- | --- |
| AI 完成 | AI 執行已確認可支援的工作，收集證據並交付判定。 |
| 使用者看指定結果 | AI 操作到指定停點，保留畫面或當次約定的證據，完成觀看後續做。 |
| 使用者操作 | 準備完成後交出起始畫面，一次引導一組動作。按指定時點取得系統證據。 |

工具可取得的值不要求使用者抄寫。需要使用者回報時，詢問具體觀察，例如是否看到指定文字。
只收到完成訊息，不能當作所有必要證據已齊全。

## 中途接手

同一時間只有一個 UI 操作者。接手先停止原操作者的 UI 動作，再交代目前畫面、已完成步驟、資料狀態及下一步。
接手者核對畫面後繼續。保留既有有效證據，不為換人重做整場。
裝置、候選或測試資料改變時，仍依原 checkpoint 規則判斷哪些證據失效。

UI 控制交接不轉移環境 owner。冷啟、資料準備、商店控制及清理仍由既定入口執行。
使用者在需要等待系統證據時先暫停相依操作。取得證據後才交接下一步。

## 相容與結果

舊測項中的使用者、Claude 或驗證者欄只是舊分工註記。
讀取時沿用操作、預期、手段與證據要求，套用本次分工，不依舊人稱拒絕可行操作。
舊 `Claude節點` 按取證節點處理。新定義依[場次格式](run_script_format.md)使用中性欄位。

實際操作者與取證者記入 session。缺證據、工具失效及清理結果分別保留。
客觀通過、使用者主觀接受及未完成檢視互不代替。
分工表只記安排，不是能力就緒、產品測試通過或外部操作授權的證明。
