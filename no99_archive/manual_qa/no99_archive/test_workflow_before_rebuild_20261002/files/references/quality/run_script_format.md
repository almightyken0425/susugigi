# 場次腳本格式

## 定位

- 場次腳本是測試定義。
- 場次腳本保存於 Quality。
- 腳本定義具體操作與證據。
- 執行結果只留 session。
- 場次不得包含帳密。

---

## 成對工件

- 每個場次包含引導檔。
- 每個場次包含步驟表。
- 引導檔定義狀態契約。
- 步驟表定義操作順序。
- fixture 是字面值權威。

---

## 場次引導

- 必填欄位：
    - 場次 id
    - 涵蓋 case
    - 前置場次
    - 起點狀態
    - 終點狀態
    - 前置能力
    - fixture 引用
    - 預估時長
    - 步驟表
- 起點必須符合前場終點。
- 鏈外場次需明示不傳遞。

---

## 步驟表

- 欄位順序固定：
    - 序
    - 測項
    - 類型
    - 動作
    - 預期
    - 取證時點
    - 手段
    - 已驗
    - 說明
- 類型值只有：
    - 操作
    - 建置
    - 還原
    - 取證
- 一列只承載一個動作。
- 取證時點寫具體狀態，例如儲存後、取消至返回設定期間或清理完成後。
- 準備與還原列也要寫核對完成的時點。取證時點不可填人或 AI 名稱。
- 動作及預期依[撰寫方法](test_step_authoring.md)。誰操作或取證只留 session。
- 已驗引用必須逐字對應。
- 建置與還原不掛已驗。

舊格式的第六欄 `驗證者` 及類型 `Claude節點` 暫時相容。
讀取時將舊人名視為非約束註記，將 `Claude節點` 視為取證節點。
同一 CSV 依表頭判斷格式。新表頭不能混用舊人名或舊節點類型。
列數、手段、檢查點與 `已驗` 的對帳要求維持不變。

---

## QA 節點

- `qa-command` 節點必須寫：
    - command id
    - scene id
    - request id 規則
- `qa-probe` 節點必須寫：
    - check id
    - expected evidence
    - 成功條件
- `qa-markers` 節點必須寫：
    - 完整 marker 名稱
    - 擷取時點
- 狀態相依節點緊接操作。
- 同時點 probe 可合併執行。
- App 無關 Jest 集中執行。

---

## 操作與分工

- 準備及系統取證沿用已確認的工具能力。
- UI 操作依[執行分工](execution_assignment.md)安排，不固定交給使用者。
- 相鄰手勢可合併成一組。
- 冷啟只在斷言需要時執行。
- 同一狀態只建置一次。
- 使用者選擇操作或觀看時，保留對應步驟及畫面停點。

---

## 選集映射

- selector 先產 case 清單。
- 以 case ID 反查場次。
- 場次是環境重放單位。
- 只判定選中 case。
- 必要建置步仍需執行。
- 選集與執行結果不落 Quality。

---

## 覆蓋

- 每個檢查點至少被引用一次。
- 例外必須附理由與日期。
- 阻礙解除後移除例外。
- 唯讀檢核器驗證雙向引用。
- 檢核器必須提供 selftest。
