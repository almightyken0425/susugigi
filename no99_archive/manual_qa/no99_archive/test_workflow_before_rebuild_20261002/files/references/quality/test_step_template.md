# 測試步驟內容範本

依[撰寫方法](test_step_authoring.md)填寫下列內容。正式測項保留既有 ID、規格引用、metadata 與場次映射。這份範本用於補齊可讀內容，不直接取代現行機器格式。

同一段能完整表達多項資訊時可合併。共用準備與資料只維護一份，引用時指出本項需要的狀態。與本項無關的條件不用列入。

```markdown
## <既有 ID 或檢查點引用> <情境與要證明的結果>

**要證明什麼**

<這項要證明的行為。若包含不同結果分支，分開列情境與判定。>
<對應規格及檢查點引用。>

**開始時的狀態**

- 畫面：<實際畫面名稱。>
- 功能狀態：<例如免費版、有效月訂閱。>
- 必要資料：<具體值或資料來源，以及需保留的比對基準。>

**開始前的準備**

| 準備內容 | 完成後應具備的狀態或證據 | 執行說明 |
| --- | --- | --- |
| <要建立的環境或資料狀態> | <接手者如何確認可以開始> | <既有方法的連結及定位> |

**操作與預期結果**

| 步驟 | 操作 | 應看到的結果 |
| --- | --- | --- |
| 1 | <使用實際畫面名稱及具體動詞。> | <可觀察文字、數量、金額或操作結果。> |
| 2 | <下一個操作或明確的準備交接點。> | <對應本操作的結果。> |

**需要保留的證據**

- <對應步驟及取證時點。需系統證據時引用執行說明。>

**結束後的狀態**

- 畫面與功能狀態：<後續可依賴的狀態。>
- 資料：<保留哪些資料，清理哪些測試資料，如何確認清理完成。>
- 下一項：<可直接接續的情境，或尚需完成的準備。>
```

下面是本次執行安排的簡表，只留在 session。沿用使用者已表達的選擇，不為填表增加一輪詢問。

| 工作 | 本次安排 |
| --- | --- |
| 準備 | 指定環境與資料準備的負責者。完成條件沿用測項。 |
| 操作 | 指定 AI 或使用者，可細分至步驟。 |
| 證據與判定 | 指定取證者。`test-run` 依測項預期核對證據並判定。 |
| 檢視 | 記錄使用者要觀看的步驟或結果。需要保留畫面時列出停點。 |
| 交接與收尾 | 記錄接手位置及清理負責者。沿用環境的單一負責者。 |

實際結果與證據引用另記在本次 session，不填回上述測項範本。
